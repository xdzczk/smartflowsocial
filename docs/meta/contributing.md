# Contributing to Documentation

**Last updated:** 2026-01-02

How to contribute to SmartFlowSocial documentation.

---

## Quick Start

1. **Find what to improve:**

   - Check
     [open documentation issues](https://github.com/xdzczk/SmartFlowSocial/issues?q=label%3Adocumentation)
   - Review [documentation TODO list](#todo-list)
   - Identify gaps or outdated content

2. **Make your changes:**

   - Edit markdown files in `docs/`
   - Follow [Style Guide](./style-guide.md)
   - Test code examples

3. **Submit:**
   - Create a pull request
   - Link to related issues
   - Request review

---

## Documentation Structure

```
docs/
├── getting-started/     # Quick start, installation, concepts
├── guides/             # User, developer, operations guides
├── reference/          # API, configuration, schemas
├── examples/           # Code examples and recipes
├── tutorials/            # Step-by-step tutorials
├── troubleshooting/    # Common issues and debugging
└── meta/              # Documentation about documentation
```

---

## Types of Contributions

### Fixing Errors

- **Typos and grammar** - Simple fixes
- **Broken links** - Update or remove
- **Outdated information** - Update to current state
- **Code examples** - Fix non-working examples

### Improving Content

- **Clarity** - Make explanations clearer
- **Examples** - Add more examples
- **Structure** - Improve organization
- **Completeness** - Fill in missing information

### Adding New Documentation

- **New features** - Document new functionality
- **Tutorials** - Step-by-step guides
- **Examples** - Code samples and recipes
- **Reference** - API and configuration docs

## Writing Guidelines

### Follow the Style Guide

See [Style Guide](./style-guide.md) for:

- Writing standards
- Formatting guidelines
- Code example requirements
- Best practices

### Key Principles

1. **Be Clear** - Write for your audience
2. **Be Complete** - Include all necessary information
3. **Be Current** - Keep documentation up to date
4. **Be Consistent** - Follow existing patterns

---

## Review Process

### Self-Review

Before submitting:

- [ ] Read through your changes
- [ ] Check all links work
- [ ] Test code examples
- [ ] Run spell checker
- [ ] Follow style guide

### Pull Request

When creating a PR:

1. **Clear title:** Describe what you changed
2. **Description:** Explain why and how
3. **Link issues:** Reference related issues
4. **Screenshots:** If UI changes
5. **Test results:** If applicable

### Review Feedback

- Address feedback promptly
- Ask questions if unclear
- Update documentation as needed
- Thank reviewers
